You are an expert team of software engineers building a high-performance logistics management platform using FastAPI, PostgreSQL, and React Native with Expo.

## Project Overview

We are building a comprehensive **DeliveryHub** system that connects businesses with drivers to manage deliveries efficiently. The platform includes features for:

- Order management
- Vehicle tracking
- Driver assignment
- Real-time notifications
- Role-based access control (Admin, Business, Driver)
- Route optimization (future phase)
- Payment integration (future phase)

## Technology Stack

### Backend (FastAPI + PostgreSQL)
- **Framework**: FastAPI (Python 3.11+)
- **Database**: PostgreSQL
- **ORM**: SQLAlchemy 2.0 (async mode)
- **Migrations**: Alembic
- **Authentication**: JWT (PyJWT), bcrypt for passwords
- **Background Tasks**: Celery with Redis/RabbitMQ
- **Real-time**: WebSocket support
- **Documentation**: Swagger UI / ReDoc (auto-generated by FastAPI)
- **Testing**: pytest, httpx
- **Security**: CORS, rate limiting, input validation

### Mobile (React Native + Expo)
- **Framework**: React Native with Expo
- **Language**: TypeScript
- **Navigation**: React Navigation
- **State Management**: Redux Toolkit with RTK Query
- **Styling**: NativeWind + Tailwind CSS
- **Maps**: react-native-maps
- **Notifications**: Expo Notifications
- **Local Storage**: @react-native-async-storage/async-storage
- **Icons**: react-native-vector-icons / expo-icon

### DevOps
- **Containerization**: Docker, Docker Compose
- **CI/CD**: GitHub Actions
- **Cloud**: AWS / GCP / DigitalOcean (TBD)
- **Environment Variables**: .env files for development, cloud secrets for production

## Database Schema Design

We will use **PostgreSQL** for relational data with strict constraints and relationships.

### Core Tables

1. **users**
   - id (PK)
   - email (unique)
   - password_hash
   - first_name
   - last_name
   - phone (unique)
   - role (admin | business | driver)
   - is_active
   - created_at
   - updated_at

2. **businesses**
   - id (PK)
   - user_id (FK → users)
   - name
   - address
   - city
   - state
   - zip_code
   - phone
   - email
   - logo_url
   - created_at
   - updated_at

3. **vehicles**
   - id (PK)
   - user_id (FK → users)
   - business_id (FK → businesses)
   - license_plate
   - vehicle_make
   - vehicle_model
   - vehicle_year
   - color
   - type (car | truck | van | bike | e-bike)
   - status (available | assigned | maintenance)
   - created_at
   - updated_at

4. **orders**
   - id (PK)
   - business_id (FK → businesses)
   - driver_id (FK → users, nullable)
   - customer_name
   - customer_phone
   - customer_address
   - pickup_address
   - dropoff_address
   - weight (kg, optional)
   - volume (m³, optional)
   - type (document | parcel | food | other)
   - status (pending | assigned | in_transit | delivered | cancelled)
   - assigned_at
   - delivered_at
   - created_at
   - updated_at

5. **driver_locations** (real-time tracking)
   - id (PK)
   - driver_id (FK → users)
   - latitude
   - longitude
   - accuracy
   - timestamp
   - created_at

6. **notifications**
   - id (PK)
   - user_id (FK → users)
   - title
   - message
   - type (order_update | alert | info)
   - is_read
   - created_at

### Relationships
- One-to-One: users → businesses, users → vehicles
- One-to-Many: businesses → orders, users → orders (as drivers), users → driver_locations, users → notifications

## API Design (FastAPI)

### Authentication Endpoints
- `POST /auth/register` - Register new user
- `POST /auth/login` - Login and get JWT
- `POST /auth/refresh` - Refresh JWT token
- `POST /auth/logout` - Logout
- `GET /auth/me` - Get current user profile

### Business Endpoints
- `GET /businesses` - List businesses (with filters)
- `GET /businesses/{id}` - Get business details
- `POST /businesses` - Create business
- `PUT /businesses/{id}` - Update business
- `DELETE /businesses/{id}` - Delete business
- `GET /businesses/{id}/orders` - List orders for business
- `POST /businesses/{id}/orders` - Create order

### Driver Endpoints
- `GET /drivers` - List available drivers (with filters)
- `GET /drivers/{id}` - Get driver details
- `POST /drivers/{id}/assign/{order_id}` - Assign order to driver
- `PUT /drivers/{id}/status` - Update driver status
- `GET /drivers/{id}/location` - Get driver location

### Order Endpoints
- `GET /orders` - List all orders (with filters)
- `GET /orders/{id}` - Get order details
- `PUT /orders/{id}/status` - Update order status
- `PUT /orders/{id}/assign` - Assign driver to order

### WebSocket Endpoints
- `ws/location/{user_id}` - Real-time driver location updates
- `ws/notifications/{user_id}` - Real-time notifications
